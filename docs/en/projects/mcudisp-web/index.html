MCU Display Web

A web implementation of the Mackie Control Universal display. Works with compatible devices, a must-have for controllers without a screen.

Python 3MIDI + OSCLAN
Downloads ↓Source code ↗
v1.2Reviewed 24 Nov 2026

A network display

  • A Python server receives display text over MIDI SysEx and timecode/transport over OSC, then sends updates to the browser through Socket.IO. Two 56-character lines provide eight seven-character channel cells.
  • Latest release: v1.2, 30 August 2025, with no binary assets. Run from source. Main differs from the tag by one README link; server code is the same.

Requirements

  • Python 3 and requirements.txt dependencies: mido, python-rtmidi, Flask, Flask-SocketIO, python-osc and eventlet. Dependency versions are not pinned.
  • REAPER, a controller or MIDI routing setup delivering the expected SysEx, a browser and a LAN. The README recommends DrivenByMoss4Reaper for MCU.

Installation

  1. Clone the repository and check out v1.2. Create a separate Python environment and install requirements.txt.
  2. In REAPER → Preferences → Control/OSC/web, add MCU or DrivenByMoss and select the controller’s MIDI input/output.
  3. Add OSC (Open Sound Control): Configure device IP + port, Host 127.0.0.1, Send to port 9000. The active ReaperOSC profile must include FRAMES s/frames/str, PLAY t/play and RECORD t/record.
  4. Run python list_ports.py. Set SEARCH_TERM in server.py to a unique part of the required MIDI input name; matching is case-sensitive.
  5. Run python server.py from the project directory. On another device open http://<computer-LAN-IP>:5000/.
git clone https://github.com/SadFrozz/mcudisp-web.git
cd mcudisp-web
git checkout v1.2
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python list_ports.py
# Set SEARCH_TERM in server.py before starting:
python server.py

Usage

  • Enable the controller’s MCU mode and route display messages to the server’s MIDI input. OSC supplies timecode and transport independently of MIDI.
  • Create func.txt in the working directory for F1–F8 names: one label per line, first eight lines only. The section is hidden if the file cannot be read. Restart the server after editing.
  • The display scales to the screen. PLAY/STOP and the green/red color scheme indicate transport and recording state.

Source-verified limitations

  • The README describes MCU-compatible devices generally, but server.py filters a specific Behringer SysEx prefix: (0, 32, 50, 0, 20, 120). Another MCU device may need parser changes; changing SEARCH_TERM alone does not guarantee compatibility.
  • OSC binds to 127.0.0.1:9000; the web server binds to 0.0.0.0:5000. MIDI selection uses the first substring match. Simultaneous DAW access depends on the MIDI driver and routing.
  • No built-in accounts, TLS or public-server setup. The code uses allow_unsafe_werkzeug=True. Use it as a local display on a trusted network.
  • There is no published minimum Python/OS matrix or coverage for all controllers. Unpinned dependencies may need compatible versions. Physical MIDI/OSC hardware was not tested while preparing this portal.

If the display is empty

  • No labels: check list_ports.py, SEARCH_TERM, MIDI routing and SysEx prefix. No timecode: check OSC port 9000 and the ReaperOSC profile.
  • If a tablet cannot reach the page, use the computer’s LAN address, the same network and firewall access to TCP 5000. A tablet’s 127.0.0.1 address points to the tablet itself.

Sources

  • No compilation step. server.py is the server, list_ports.py lists inputs and templates/index.html is the UI. Run locally: GitHub Pages cannot execute Python or connect MIDI devices.
