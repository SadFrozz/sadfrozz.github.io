Ath10k-airport

An experimental Qualcomm Atheros Wi-Fi driver for macOS, controlled through the system Wi-Fi menu.

macOS SequoiaOpenCoreQCA9377
Downloads ↓Source code ↗
No releaseReviewed 24 Nov 2026

Development status

  • A native OpenCore kext for scanning, association and IPv4/IPv6 traffic without a companion app, login agent, OCLP or system-volume patches.
  • There are no published GitHub Releases. Main’s 1.0.105 is driver metadata, not a stable packaged release. native-sequoia-development contains later work and a status map with a 1.0.114 checkpoint.
  • The development branch README repeats older descriptions. Read docs/development/NATIVE-STATUS.md and its implementation for branch-specific scope rather than relying on that README alone.

Requirements and evidenced scope

  • Hardware checkpoint: QCA9377 PCI 168c:0042, subsystem 1a3b:2b51 on x86_64 macOS Sequoia 15.6.1 (24G90). Firmware files do not establish support for other cards or macOS versions.
  • OpenCore with a validated configuration, a preserved working EFI and an alternative network connection. macOS 11–26 is a development target, not a supported-version matrix.

Build and installation

  1. No release package is currently published. First select a pinned source commit for your intended task and read the compatibility guide.
  2. macOS builds require the Apple command-line toolchain, Python 3 and pinned submodules. The standard main build follows below; output is build/native/out/Ath10kMac.kext.
  3. Preserve the working EFI. Copy a functional Ath10kMac.kext into EFI/OC/Kexts and add/update its enabled Kernel → Add entry in config.plist.
  4. Validate OpenCore configuration and OS/hardware suitability before rebooting. After loading, use the standard Wi-Fi menu and verify the actual loaded build.
  5. Do not install controller-only DIAGNOSTIC_STAGE=3 or cryptography diagnostics as functional Wi-Fi drivers.
git clone --recurse-submodules https://github.com/SadFrozz/Ath10k-airport.git
cd Ath10k-airport
make -j2 kext
# Local regression suite:
make test-development

Usage and branches

  • Main: native scanning, WPA2-Personal and opt-in experimental WPA3-SAE/PMF. SAE is disabled by default. The README specifies NATIVE=1 NATIVE_SAE_EXPERIMENTAL=1 NATIVE_PMF_PROBE=0 DIAGNOSTIC_STAGE=0.
  • native-sequoia-development adds OWE, WPA1, WEP and Enterprise/EAP paths. Its status map reports bounded hardware successes for OWE/OWE Transition, WPA1-CCMP, WPA2 and WPA3, but no stable Enterprise acceptance. A mixed TKIP+CCMP observation does not establish pure TKIP operation.
  • Development observations do not automatically apply to main. Use that branch’s own contracts, build flags and status map linked below.

Limitations

  • A development driver: prolonged stability, latency, transmission errors and disconnects remain under investigation. Short successful traffic is not interoperability certification.
  • WPA3/PMF are implemented with bounded hardware observations. Full interoperability, group BIP and AP-triggered rekey still need hardware evidence.
  • Host-requested roaming has local regressions; physical inter-AP handoff is untested. Sleep/wake is labelled possibly working, with platform sleep investigation deferred.
  • AWDL/AirDrop and FT/SAE-PK are not implemented. Main does not advertise Enterprise; development includes EAP work without stable hardware acceptance. Do not infer support for all macOS versions or Qualcomm cards.
  • The root license does not automatically cover firmware and dependencies. The public license audit records unresolved compatibility questions.

Diagnostics

  • Report the macOS build, PCI/subsystem IDs, actual loaded driver version/UUID and reproduction steps. Remove SSIDs, MAC addresses, passwords, keys and personal paths from shared diagnostics.
  • If the kext does not load, check OpenCore Kernel → Add, dependencies and the selected artifact’s signature. Restore your saved working EFI if needed.

Verification behind this page

  • Reviewed README, compatibility, native guide, status maps, changelog, NativeProfile/radio source and differences between both current branches. Checked branch lists and the absence of published releases.
  • No driver build, installation or radio testing was performed for this portal. Hardware results here are scoped statements from the public status map, not new tests.
